# KAYAN offline pilot protocol

The research workspace is separate from the operational repository. The source baseline is local HEAD `421b908bc07d16ee624e850b0f49e5c94a1ce6ba`, with existing local handoff and evidence changes. The live code validates the fixed Recon → Web-App → Network → Reporting roster after the Planner call. A process-local lock serializes streaming inference against the shared local model. The configured primary is Qwen2.5 7B, with Qwen2.5 1.5B selected if the primary is absent, 4,096 context tokens and a 384-token output cap. Reporting uses verified finding IDs and specialist coverage. TrustGate authorization stays independent of all research scheduler and model decisions. The historical Planner scores and grounding-on/off results are retained separately from this pilot.

Source locations at the pinned commit are `pentagi/live_engagement.py` for assignment, specialist outcomes and reporting, `pentagi/ollama_client.py` and `config/llm.json` for inference, and `trustgate/service/src/{authorize,policy,roe,audit}.rs` for policy checks, signed engagement scope and the audit trail. The reference copies are byte-matched to the pinned Git blobs. The pilot host had a Ryzen 9 8940HX, 31.2 GiB of physical RAM and an RTX 5060 Laptop GPU with 8,151 MiB of VRAM. ## Order of work

1. Inspect source, configuration, retained evaluations, installed model manifests, VRAM and RAM. Stage only selected existing models into the research model store and verify their content digests. Check an isolated loopback Ollama process with cloud disabled, one slot and at most one loaded model.
2. Freeze role inputs, expected outcomes, output schemas and generation settings. Validate the scorer against independently derived reference labels and malformed, unsupported and missing outputs. Score held-out cases with fixed prompts. Keep calibration families separate.
3. Run Qwen2.5 7B first, then run compatible comparison checkpoints using the same case order and generation controls. Report first attempts and one structural-repair attempt if applicable. No correction uses held-out answers. The frozen runner builds structural error lists from a set intersection. If future arms trigger corrections, use a fixed PYTHONHASHSEED for replay because the ordering of repair hints can vary. The first four holdout arms did not trigger repairs. Qwen3 used PYTHONHASHSEED=0 and triggered two repairs, which did not rescue an exact pass. Capture response text, role-level label and evidence metrics, token counts and latency. External resource samples are system-wide and identify the measurement window.
4. Independently compare serial and dependency-aware task scheduling with fixed fixture graphs, synthetic work delays and one mock inference slot. Counterbalance run order and require equivalent terminal states. Exercise an inert broker with both expected denials and authorized effects.
5. Independently compare ATT&CK retrieval arms on archived-style synthetic defensive excerpts. Freeze the index, isolate ATT&CK from skill and OWASP context, and score labels and evidence support separately. Report abstentions and false promotions. Run a separate fixed-checkpoint Qwen mapping ablation to measure LLM outputs. The deterministic retrieval pilot and the Qwen mapping ablation leave adapter effects unmeasured.
6. Summarize measured results with raw counts, paired intervals where applicable, failures and exclusions. Keep timings over mock delays separate from actual Ollama response time.

## Comparison boundaries

- All five role equivalents consume authored records or inert task IDs. No model output is dispatched, passed to a shell or used to build a target request.
- This is a small synthetic pilot. It does not estimate general security accuracy, live performance, or full model semantic fidelity. The holdout families are separate from calibration cases, but the scoring contracts and ground truth are authored for this pilot. Human review on outside data is needed for confirmation.
- No live assessment, scan, exploitation, new ROE, operational audit/session write or policy change belongs to this study. Public model/corpus downloads and loopback inference are separate research dependencies.
- Report GPU backend and model package explicitly. A failed smoke or package download is a recorded exclusion. If multiple inference slots, per-role deployment, or adapter training are not actually run, leave them unmeasured.
- The architecture study uses a mock fixed serial flow that represents the order constraint of the operational baseline. It is not a timing run of the live code. Security checks in the mock broker and any Rust unit tests are separate evidence.

## Reproduction and files

Run from this workspace. Use PowerShell 7.4 or later for the supplied Windows launcher. The source model manifest paths are in `stage_models.py`. An Ollama 0.40.13 process on a dedicated research loopback port needs `OLLAMA_MODELS` pointing to `models`, `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1` and `OLLAMA_NO_CLOUD=1`. The supplied logs identify the backend actually used. Model packages are external dependencies and are excluded from the evidence bundle.

- `python -B model_bench.py run --model qwen2.5:7b --split heldout --port 11437` runs the matched baseline against the research endpoint. Use a fresh copy with empty results paths for each reproduced arm and any fixed-path summary. Use the same model package digest and compare run manifests before treating the outputs as a matched arm.

Then run `python -B run_challengers.py --wait-minutes 60` with the one-slot endpoint active on 11437 and empty result paths for the challenger arms. Both listeners use the same research model store.
- Run the same command with `llama3.1:8b` for the installed challenger. Run `python -B compact_control.py` for the 1.5B compact holdout and add `--split calibration` for its calibration arm. The latter extends the allow-list for this checkpoint and reuses the frozen runner as-is.

### Cedar unit-build preflight

Use an isolated copy of the source and a host permitted to run Cargo-built executables. The copied service has a binary target. The original --lib preflight produced “no library targets found.” The corrected test command requires the locked crates to be available in the offline Cargo cache.

Run with fresh temporary test keys in the test shell. The ROE fallback path otherwise points two levels above the service manifest and can read or create a persistent key. The full suite also includes a legacy health test with an absolute, user-specific audit path. Exclude that test when replaying the suite on a different machine. No service startup is needed.

~~~powershell
$env:TRUSTGATE_ROE_KEY = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:TRUSTGATE_HMAC_KEY = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
try {
    cargo test --locked --offline --manifest-path reference-gate/Cargo.toml --target-dir rust-build -- --skip test_health_structural
} finally {
    Remove-Item Env:TRUSTGATE_ROE_KEY, Env:TRUSTGATE_HMAC_KEY
}
~~~

## Primary research references

- Kim et al., *Capable language models can outgrow the benefits of collaboration*, Nature Machine Intelligence 8, 1157–1172, 24 July 2026, DOI 10.1038/s42256-026-01268-y. The authors matched prompts, tools and compute across 260 configurations, five topologies and six benchmarks. The reported 87% topology-selection result applies within the studied domains. It motivates matched architecture controls. [Journal article](https://www.nature.com/articles/s42256-026-01268-y)
- Yu et al., *Toward Scalable LLM-Based Multi-Agent Collaboration*, Electronics 15(11), 2475, 4 June 2026, DOI 10.3390/electronics15112475. A dependency-aware implementation reduced execution time by 21.3–33.0% against its internal serial arm on four RTX 3090 GPUs. The study used one application domain and did not inject task failures. It motivates the overlap comparison. [Journal article](https://www.mdpi.com/2079-9292/15/11/2475)
- Amine and Saab, International Journal of Information Security 25, 183, 5 November 2026, DOI 10.1007/s10207-026-01350-x. In the controlled subset of 80 benchmark cases across two passes, model escalation had an odds ratio of 8.79 [3.39, 22.81]. The architecture main effect was inconclusive, OR 1.17 [.85, 1.62]. The evaluated system used one active specialist. This supports isolating checkpoint and coordination changes as separate experiments. [Journal article](https://link.springer.com/article/10.1007/s10207-026-01350-x)
- Peters-Gill et al., *Can CaMeLs Talk?*, arXiv preprint v1, 5 October 2026, DOI 10.48550/arXiv.2610.05640. The provenance-preserving arm observed 0.0% attack success in the tested MultiAgentDojo hierarchy versus 0.2% for individually protected agents and 12.9% unprotected. The control-flow argument covers tree topologies. Shared-state and asynchronous DAGs remain open, and the paper reports utility costs. This motivates measuring handoffs and legitimate task completion separately. [Preprint](https://arxiv.org/abs/2610.05640)
- Resul et al., *CTI-Rationale*, Journal of Cybersecurity and Privacy 6(6), 190, 2 November 2026, DOI 10.3390/jcp6060190. The corpus contains 1,740 human mappings across 100 reports. Over 228 labeled test paragraphs, retrieved label-only demonstrations increased Haiku micro F1 from .367 to .500 and retrieved full-evidence demonstrations scored .475. The Sonnet improvement was inconclusive and candidate negatives lacked human validation. This motivates separate technique and evidence scoring. [Journal article](https://www.mdpi.com/2624-800x/6/6/190)
- Debenedetti et al., *AgentDojo*, NeurIPS 2024 Datasets and Benchmarks Track, DOI 10.52202/079017-2636. The paper includes 97 realistic tasks and 629 security cases. Models sometimes failed on benign tasks, supporting separate reporting of legitimate utility and prevented effects. The tested application environments differ from KAYAN's mock broker. [Proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/97091a5177d8dc64b1da8bf3e1f6fb54-Abstract-Datasets_and_Benchmarks_Track.html)
- Zhao et al., *Bias-Aware Orchestration*, Findings of EMNLP 2026, 24–29 October 2026, DOI 10.18653/2026.findings-emnlp.2055. Role auditions and aggregation reached an 88.86% length-controlled win rate on AlpacaEval 2.0 with the selected assignment. This is an instruction-following result with a distinct model pool and evaluator. The transferable design is to separate role selection from held-out scoring. [Proceedings](https://aclanthology.org/2026.findings-emnlp.2055/)
- Candidate checkpoint documentation provides license and quantization metadata. The Qwen3 8B and Granite 4.2 8B tags reviewed are Apache-2.0, Q4_K_M, and approximately 5.2 and 5.3 GB respectively. [Qwen3 package](https://ollama.com/library/qwen3:8b) · [Granite package](https://ollama.com/library/granite4.2:8b)
- The additional Q4_K_M package options are Granite 4.2 3B at approximately 2.2 GB, Qwen3.5 4B at 3.3 GB and Qwen3.5 9B at 6.6 GB, each Apache-2.0. Package size is separate from model residency with runtime state and a 4,096-token context. The 9B arm needs a dedicated feasibility check before a timed comparison. [Granite 3B](https://ollama.com/library/granite4.2:3b) · [Qwen3.5 4B](https://ollama.com/library/qwen3.5:4b) · [Qwen3.5 9B](https://ollama.com/library/qwen3.5:9b)
- RedSage was published at ICLR 2026 and reports gains on the authors' own cybersecurity and general benchmarks. Those scores use different workloads and do not establish equivalent quantized results. The DPO weight license discussion records a scoped research-use confirmation for the requester. It does not supply a general redistribution license for the weights. This pilot did not download or run the model. [Proceedings version](https://openreview.net/pdf/369847e5bc9839b6b81a74d6c95151991212e18d.pdf) · [Publisher's clarification](https://github.com/RISys-Lab/RedSage/issues/15)
