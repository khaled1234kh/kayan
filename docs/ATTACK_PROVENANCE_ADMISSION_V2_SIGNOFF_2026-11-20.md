## Findings requiring an owner decision

**1. High for study validity · The attestation erases the distinction between omitted ancestry and an explicit root.** The submitted source must explicitly contain `upstream`. But the external issuer validates a source and hashes its default-filled dump. An external declaration with the field omitted and one with `upstream=[]` therefore produce identical inputs to SHA-256. The receiving registry checks field presence only on the submitted row. This matters when the independent attester and snapshot custodian hold different declarations. [Source default](../eval/attack_fact_registry_v1.py#L32) · [Digest membership check](../eval/attack_fact_registry_v1.py#L225) · [Synthetic attestation issuer](../eval/fixtures/ai/attack_admission_v2.py#L18)

Minimal paired reproduction using the existing v2 Slate fixture: keep the submission's four explicit root declarations. In a **separate copy** of the external catalogue, omit only the backup-service upstream field. The issuer returned exactly the same digest set as for four explicit roots. The normal v2 entry point returned `all_eligible` with T1486 and T1490. With the same manifest, payloads, case assignment, head, receipts and time, withholding the backup-service attestation yielded `mixed`, T1486 alone, and `independent_attribution_missing` for T1490. No real collector dependence is alleged. The defect is that the verifier cannot distinguish the two external declarations.

**Correction and required regression.** At issuance, decline to attest a source with undeclared ancestry. Version the attestation representation and retain field presence in the verifier's expected commitment. Bind the attestation or its authenticated enclosing approval to the assigned case and snapshot. Test independently constructed external and submitted catalogues in both omission directions, an explicitly attested root, a shared parent and a different case/head. Require the backup claim to remain withheld whenever the external declaration is incomplete. Existing tests cover omission on the submitted side and absent approvals. [Existing ancestry matrix](../tests/test_attack_evidence_admission_v2.py)

**2. Medium for study validity · A denial about a different session can veto a correct finding.** Use the existing Slate positive process-link control. P7 is linked to B19 and both findings qualify. Add an uncited reviewed `unlinked` assertion for P7, holding case, event, process, tenant, asset, principal and generation constant. Naming **B19** correctly withholds T1486 and preserves T1490. Naming **a distinct session** produces the identical withholding and `conflicting_or_superseded_evidence`. “P7 is linked to B19” and “P7 is unlinked from the other session” are compatible. This is a false rejection. The applicability check admits different sessions so competing affirmative links can reach the guard, then strict projection turns a negative link into an event-wide veto. [Applicability](../eval/attack_fact_guard_adapter_v1.py#L25) · [Veto projection](../eval/attack_fact_guard_adapter_v1.py#L102)

**Correction and required regression.** Determine which process/session pair a negative assertion denies before projecting a veto. Preserve uncertainty where the relationship cannot be resolved and preserve the existing conflict check on two affirmative sessions. Pair the two denials above with two competing affirmative links. Check both input orders, the uncited decision, the disposition of an explicitly cited irrelevant denial and the independent sibling.
