# Offline ATT&CK / OWASP grounding

`index.json` is generated by `python -B -m grounding.build_index` from official repository snapshots. It retains source URLs, commit IDs and SHA-256 hashes. Runtime retrieval never accesses the network.

Sources:
- [MITRE ATT&CK STIX data](https://github.com/mitre-attack/attack-stix-data): Enterprise, Mobile and ICS techniques and subtechniques. Revoked/deprecated entries remain in the stored inventory with explicit flags and are excluded from retrieval.
- [Official OWASP Top 10](https://github.com/OWASP/Top10): the current 2025 categories plus explicitly historical 2021 entries for reference. Runtime retrieval excludes the historical version. IDs keep their year; A03:2021 and A05:2025 are distinct records.

The checked snapshot contains 1,204 records: 1,184 ATT&CK records and 20 OWASP records. Runtime filtering leaves 945 active/current records (935 ATT&CK and ten OWASP). The default retrieval domain is Enterprise; Mobile and ICS are stored and available through the `domain` parameter. Corpus-size counts describe inventory, not tool coverage.

The builder pins MITRE commit `c2494b29dd268c46a5d0ea0990553e4327cd2253` and OWASP commit `3a31f35346c3f4e90f350395124382fa53af2afe` in the checked index. Rebuilding intentionally refreshes those pins and records the new hashes; it is not required for normal runs.

`retrieval.py` implements deterministic TF-IDF cosine ranking of task tokens against names, descriptions and keywords. It returns one to three entries with source attribution. Description budgets are A=400, B=900, C=1,800 characters; tier labels control depth independently of model resolution. The index and its descriptions are reference data, not instructions or ROE authority.

`pentagi/call_context.py` adds retrieval beside the existing curated skill context. Tool executors receive this under `_kayan_context`; reporting records its generation context. The older orchestrator is a deterministic baseline. The live_engagement engine now injects bounded excerpts into actual local Qwen calls and records the exact model input. The pinned skills/library_index.json adds 818 third-party reference packets. No embeddings or fine-tuning are used. Real grounding quality must be measured rather than inferred from retrieval wiring.

Evaluation uses the existing harness:

```powershell
python -B -m eval.scope_violation_tests.run_eval --grounding-comparison
```

Results are in `eval/reports/grounding_comparison_results.json` and `.md`. The accuracy field explicitly measures evidence-backed precision on the four vulnerability reports, excluding informational discoveries. It checks captured raw HTTP response evidence rather than trusting the detector's boolean flag. General classification accuracy is left null because no blinded positive/negative benchmark exists. The existing coverage tracker includes declared techniques and only five lab labels; the finding-only metric uses the six existing reporting labels. Neither measures coverage of all ATT&CK.

Source attribution and licenses are retained in licenses/MITRE_ATTACK_LICENSE.txt and licenses/OWASP_TOP10_LICENSE.txt. The OWASP descriptions are normalized adaptations of the cited official categories under CC BY-SA 4.0; retain their attribution and license when redistributing the derived index. MITRE copyright and license are reproduced in the MITRE license file.

Actual-model comparison commands (authorized lab, live model, console and gate must already run):
~~~powershell
python -B -m eval.live_runtime_check --grounding off
python -B -m eval.live_runtime_check --grounding on
~~~
See eval/reports/live_grounding_comparison.md for the measured adverse result and exact coverage/count definitions. These runs also check live WebSocket output, five session endpoints and governed operator delivery; they do not inspect browser pixels.
